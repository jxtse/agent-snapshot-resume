# Replay lifecycle and environment fixes

All changes are confined to `fix/replay-bg-env`. No sandbox, model request, commit, or push was performed.

- Failed background dispatch is no longer treated as a successful completed command by the lenient gate. Recorded terminal status is authoritative. Known timeout/kill exits (124, 137, 143, 144) use `bg_duration_s + 0.25s`, bounded by the execution cap; timeout uses TERM, 137 uses KILL, and CC's 144 termination convention uses TERM. Reports distinguish `bg_termination_reproduced` and `bg_failure_reproduced`. A lower execution cap remains a replay timeout, never a reproduced historical kill. Fast ordinary failures are bounded too, but a timeout is never converted into exit 1/2.
- Later consumers of failed background output must reproduce exactly/normalized; missing consumers or changed numeric reads block acceptance. Read evidence is now included and compared against actual file lines. When a full historical Read is available, the producer output must be a numeric-tolerant prefix match. Unavailable historical output is not fabricated. Every output file still contains actual replay bytes and its hash.
- Background completion notification line is retained separately from dispatch observation line. Tail plans retain jobs dispatched before the base snapshot but finished at/after it. Since source cleanup stops old CC (which writes completion trailers), the replayer identifies cloned writers by their exact output-file descriptor through Linux `/proc`, stops their process groups, checks the descriptors close, then reruns the job in the foreground before dependent actions. Report fields record this rerun and stopped groups; inability to identify/check ownership fails closed. This is a replay from the snapshot's filesystem, not a rollback of pre-snapshot partial writes.
- `prepare-snapshot` and `batch` accept `--replay-deadline-s`, default 10800. It reaches dispatch, polling, state receipts, and the sandbox lifetime (deadline plus preparation margin). Existing per-command caps remain separate.
- The narrow `harness_path_only` rule accepts a missing terminal `ls` of configured `plan.harness_owned_paths` (defaults: `/opt/tbs-proxy`, `/opt/asr-proxy`, `/logs/agent`, `/tmp/.asr-resume`). It requires unchanged preceding output through a literal echo boundary and a conservative command whitelist. Writes, substitutions, conditionals, unexpected stderr, and changed package output remain blocked. This covers the observed `pip list ...; echo ---; ls /opt/tbs-proxy` probe.
- Each replay command uses a login shell. An unambiguous literal PATH in archived `agent/sessions/shell-snapshots/*.sh` is captured in the bundle and applied after login initialization. No archived shell code or secrets are sourced. Missing/ambiguous snapshots use the image's login environment, recorded in each result. Completed background budgets use total `bg_duration_s` even if the dispatch observation mentions a foreground timeout.

## Evidence and boundaries

Read-only evidence: `../asr-dsv4-o70-hint-20261113/state/*replay_report.json` and `batch/{r1b,r2}/units/*/bundles/*/plan.json`.

- certified-sparse-regression's original and replay exit 124 were rejected because dispatch `is_error=false` reached the foreground success check. foraging-cognitive-model and inverse-waveguide-shape expose the same lifecycle problem with killed jobs and inflated replay budgets.
- traffic-flux-inversion's `fullpipe2.py` dispatch is already ordered before its Write (04:31:45 versus 04:33:20 UTC). The earlier `pkill -f ...; cat > fullpipe2.py` originally exited 144. Reordering the later Write would not fix this causal divergence. The new fast-failure cap prevents a 900-second run, but if the missing-script failure cannot be reproduced, the gate still blocks. No deletion of snapshot files or invented exit 2 is performed.
- r2 linked-cell-suppression and energy-routing tail plans contain no background actions despite dependencies on background artifacts/logs. The former observation-line-only filter could drop these jobs. Rebuilt plans retain incomplete jobs using completion lines. Existing saved plans must be rebuilt; they cannot recover omitted actions themselves.
- sparse-network-assimilation's pip command actually returned rc 0 in 126.91 seconds with a 325-second budget, consistent with its 147.8-second background duration. The final scipy probe and pipeline hide pip's own outcome. Thus the evidence does **not** establish a short replay timeout; changing that budget alone cannot certify torch installation. Login/PATH parity is improved, but installation success requires a new replay and the later import gate; no package failures are waived.
- stereo-dem-icesat2 has an archived shell-snapshots directory but no snapshot files in the inspected trial. No historical PATH was invented. Login-shell fallback uses image configuration; live parity remains unverified under the no-sandbox constraint.
- Numeric drift in output that is subsequently consumed remains blocked unless the consumer itself is exact/normalized. Unknown completion, missing output hashes, missing Read evidence, and mismatched termination outcomes are not relaxed.

Validation: full offline pytest suite using `env -u PYTHONPATH uv run --project . python -m pytest -q`; 346 passed, 1 skipped, 7 subtests passed (13.68 seconds). Regression tests cover lifecycle termination, fast-failure order/capping, consumed-output rejection, snapshot tail boundaries/rerun ordering, total-duration budgets, harness write rejection, deadline forwarding, and captured PATH precedence. No paid integration validation was run.
